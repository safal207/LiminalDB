# Governance

This project is currently maintainer-led.

## Leadership

- Project Lead / Maintainer: Aleksei Safonov

The Project Lead has final decision authority for roadmap, architecture, security posture, and release readiness.

## Decision Process

1. Proposals are raised in GitHub issues or pull requests.
2. Discussion is public and consensus-seeking by default.
3. If consensus is not reached in a reasonable time, the Project Lead decides and records rationale in the thread.

## Maintainer Appointment

New maintainers may be appointed based on:

- sustained, high-quality contributions,
- reliable review and community conduct,
- demonstrated alignment with project goals and Code of Conduct.

Appointments are announced publicly in the repository.

## Maintainer Removal

Maintainers may be removed for:

- prolonged inactivity,
- serious or repeated policy/Code of Conduct violations,
- sustained failure to fulfill role responsibilities.

Removal decisions are documented with rationale.

## Project Lifecycle and Wind-Down

If the project is no longer sustainable:

1. Move to maintenance mode (critical fixes only).
2. Publish a status notice and target timeline.
3. Invite steward transfer to qualified maintainers/organizations.
4. If no successor is found, archive repositories as read-only.
5. Keep source history, license terms, and docs available.

## Conduct and Transparency

The project follows `CODE_OF_CONDUCT.md` and uses repository-first, public decision records for significant technical and governance decisions.
